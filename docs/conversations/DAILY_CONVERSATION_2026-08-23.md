# 2026-08-23

## The changelog existed three times and all three disagreed (issue #8)

The user opened `yantrakit.com/flowchart-react?path=/docs/getting-started-changelog--docs` and
said it was outdated. It was, and the cause was not a stale deploy.

```
src/Changelog.mdx   [1.1.3]     the page being served
CHANGELOG.md        [1.1.5]
npm latest           2.0.1
```

`src/Changelog.mdx` was a hand-written second copy of `CHANGELOG.md`. Nothing compares two prose
files, so both went stale — and they went stale at *different* points, which is the tell that the
problem is structural rather than neglect. The whole v2 clean break was missing from both.

Worth recording because it defeated a casual check: the deployed Storybook's **stories** were
current — `author-with-text` is a v2 story — so an inspection of story IDs said the deployment was
fine. It was the prose beside them that was two versions behind.

### What was done

- `[2.0.0]` and `[2.0.1]` reconstructed in `CHANGELOG.md` from `25aaeec` (#5) and `6600689` (#7),
  cross-read against `MIGRATION.md` and `AGENTS.md` §7 for the breaking changes and the removals.
  The `2.0.0` entry carries a **Not supported** section for the same reason `AGENTS.md` has one.
- `src/Changelog.mdx` is now generated by `scripts/generate-changelog-mdx.mjs`, wired into both
  `storybook` and `build-storybook`, and gitignored. One source; the copy cannot drift again.
- Verified on the built bundle rather than the source: the assets went from `[1.1.1] [1.1.2]
  [1.1.3]` to all seven versions. Base path `/flowchart-react/` and 13 stories unchanged.
- `tsc --noEmit` exit 0, `eslint src/` exit 0, `Tests 162 passed (162)`.
