# src/parse — Mermaid-like flowchart DSL ⇄ IR compiler

## Concept
This folder is a pure-TypeScript, bidirectional compiler between a Mermaid-like flowchart DSL (plain text) and this
package's renderer-agnostic intermediate representation (`iFlowGraph`, defined in `src/ir/types.ts`). `parseFlowchart`
reads DSL text and produces an `iFlowGraph`; `serializeFlowchart` takes an `iFlowGraph` and produces DSL text back.
It exists so a diagram can be authored/edited/stored as short, human-writable text (or generated by an LLM) while every
downstream layer (paths, layout, react) consumes only the typed IR and never touches text. There is no HTTP, DB, or
UI surface in this folder — it is a synchronous, side-effect-free text↔object transform consumed in-process by any
TypeScript/JavaScript caller, inside this package or in a host app that imports `@yantrakit/flowchart-react`.

## Files
1. `src/parse/parseFlowchart.ts` — `parseFlowchart(text, options?)`: tokenizes + parses DSL text into an `iFlowGraph`.
2. `src/parse/serializeFlowchart.ts` — `serializeFlowchart(graph)`: renders an `iFlowGraph` back to DSL text.
3. `src/parse/errors.ts` — `FlowchartParseError`: the single error class `parseFlowchart` throws on malformed input.
4. `src/parse/index.ts` — SETUP: barrel re-exporting `parseFlowchart`, `iParseOptions`, `serializeFlowchart`,
   `FlowchartParseError` for `src/index.ts` (the package root barrel) to re-export.

## Out of scope
- Grammar not implemented: `subgraph`/`end` blocks, node/edge `style` and `class` (CSS-like) statements, `click`
  interaction directives, multi-line node labels, quoted labels containing the shape-closing characters (`]`, `}`,
  `)`), any Mermaid diagram type other than `flowchart`/`graph`.
- Semantic graph validation beyond what the grammar itself enforces (e.g. this folder does NOT reject a graph with
  disconnected components, duplicate edges, or a node id referenced only as an edge endpoint and never declared with
  a shape — those are accepted structurally).
- Rendering, layout, positioning, or path/route detection — owned by `src/layout/` and `src/paths/` respectively,
  which consume the `iFlowGraph` this folder produces.
- Validating the resulting `iFlowGraph` against `FLOW_GRAPH_SCHEMA` (Zod) — owned by `src/ir/schema.ts`; this folder's
  contract is the DSL grammar only, not IR-shape validation.
- Any React/UI rendering of the parsed graph — owned by `src/react/`.
